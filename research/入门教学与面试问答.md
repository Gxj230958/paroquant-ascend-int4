# 低位宽模型执行入门教学与面试问答

## 1. 一句话结论

这个项目让已经压缩好的 ParoQuant 大模型在昇腾卡上直接使用紧凑权重，并把多次旋转处理合在一起，减少中间数据读写和显存需求。

## 2. 背景与用途

大模型有很多权重，可以把它们理解成模型做计算时使用的大量数字。权重占据不少显存，因此可以用位数更少的数字近似保存它们。

但是，文件更小不代表运行就高效。如果每次计算前都把整份压缩权重展开，再写到显存里，既花时间，又可能抵消压缩的好处。

ParoQuant 已经给出了压缩方式、旋转参数和公开模型。本项目直接使用公开的 Qwen3-4B-PARO 与 Qwen3-8B-PARO，重点解决这些已有内容怎样在昇腾上执行，不重新训练一套量化算法。

## 3. 核心概念

### 权重与线性层

**大白话：** 线性层是模型里反复出现的一类计算：把一组输入数字，按权重进行乘加，得到另一组数字。

**例子：** 输入是 2 和 3，某个输出的权重是 4 和 5，那么它的一部分计算就是“2 乘 4，加上 3 乘 5”，结果为 23。真实线性层同时处理许多这样的输入和输出。

### 四位权重

**大白话：** 一个权重用四个二进制位存编码，可以表示的不同编码很少，需要配合比例和偏移，近似恢复原数值。

**例子：** 假设编码是 9，偏移是 8，比例是 0.1，那么恢复的权重为 0.1。先减偏移，再乘比例，是理解这种权重格式的关键。

本项目的紧凑计算路径使用四位权重和十六位输入，常用名称是 W4A16。整个模型的显存不只包含权重，还包括输入、中间结果和额外存储，所以总显存不会自动变成原来的四分之一。

### 旋转

**大白话：** 这里的旋转是改变一组数字的表示方向，让它们更适合低位宽表示，不是旋转图片。模型使用的是公开权重配套的旋转参数。

**例子：** 在二维平面上，把坐标轴转一个方向，同一个点可以用另一对坐标描述。要保留原计算含义，相关的权重和输入处理必须匹配，不能随便转一边。

实际模型会对成组通道做多级成对旋转。入门时先理解“配套的数字表示变换”即可。

### 融合与打包

**大白话：** 融合是把连续的小处理放到一次计算里，少把中间结果写回显存；打包是把多个小编码紧凑地放在一个较大的存储单元里。

**例子：** 八个四位编码可以装进一个三十二位存储单元。原模型与昇腾算子对这八个位置的排列要求不同，就需要重新整理。整理时既要改排列，也要正确处理编码的正负表示和偏移。

本项目把八级旋转融合，同时把原来的权重排列转换成原生四位算子支持的排列。仍然保留逐级舍入规则，不能为了融合而擅自改变数值过程。

## 4. 用一个小例子走一遍

先用教学数字说明“换编码但不换含义”。

假设原权重编码是 9，偏移是 8，比例是 0.1。恢复后是 0.1；输入为 2 时，对乘加结果的贡献就是 0.2。

如果目标算子要求有符号编码，可以把编码改成 1，并相应调整偏移。只要恢复后仍然是 0.1，数学含义就保住了。真实实现对全部打包位置做这样的配套转换，再交给硬件算子。

模型运行时，流程可以这样理解：先准备好符合昇腾要求的紧凑权重；输入经过配套旋转；再用紧凑权重做矩阵计算。融合核尽量在内部完成多级旋转，减少反复写中间张量。

为了判断价值，项目比较了三种主要执行方式：每次展开整层权重、提前展开并长期保留，以及保留紧凑权重。后两种都使用融合旋转，避免拿一个明显低效的版本作唯一对照。

以 4B 模型、2,048 单位正文输入为例：提前展开的强对照峰值约 8.142 GiB，每秒生成 23.854 个单位；紧凑路径峰值约 4.857 GiB，每秒生成 22.656 个单位。这次主要交换的是“更少显存”与“略低速度”。

所有已测模型和长度中，紧凑路径相对同一量化权重的强对照，峰值显存降低 38.9%–42.1%，解码吞吐降低 5.0%–18.1%。原始未量化的浮点模型在本机更快。

模型质量另作检查。完整 1,319 道数学应用题测试中，紧凑路径的 4B、8B 准确率分别为 89.54%、87.11%；原始浮点模型为 90.52%、87.34%。它们对应固定提示、非思考模式和最多 512 个新单位的生成协议。

## 5. 常见误解

- **“四位权重意味着整个模型都用四位数。”** 输入和许多其他计算仍使用浮点数，压缩的主要对象是指定线性层的权重。
- **“旋转是本项目新训练出来的技巧。”** 旋转参数来自公开 ParoQuant 模型，本项目负责执行和融合。
- **“比朴素版本快几十倍，就说明超过了正常浮点模型。”** 朴素版本反复展开权重，成本很大。与强对照和原始模型的结果必须分别说。

## 6. 上手步骤与检查清单

1. 从[昇腾使用说明](../ASCEND.md)开始，先确认下载的是带配套量化信息的 PARO 权重，而不是只拿一个普通模型文件。
2. 先读懂上面的编码恢复例子，再运行 `experiments/ascend_correctness.py`。启动前加载昇腾环境并确认目标卡健康、空闲。
3. 先比较一个线性层：相同权重、相同输入，紧凑路径与展开参考输出应在已验证的误差范围内接近。
4. 再比较完整模型。区分输入处理到第一个输出的时间，以及后续连续输出的速度；把权重准备、首次执行和预热单独记录。
5. 最后看完整文本预测和数学题评价。单层误差小是必要检查，但不能代替模型级质量测试。

## 7. 一句话总结

这个项目把现成的低位宽模型变成昇腾上可用的紧凑执行路径，并测清了它省显存所付出的速度与质量代价。

## 面试问答

### 问题一 你的工作与 ParoQuant 原算法有什么区别

**中文回答：** 原算法和公开模型已经提供量化权重与旋转参数。我没有重新学习这些参数，而是实现昇腾上的融合旋转、紧凑格式转换和矩阵执行，并验证完整模型的性能与质量。

**Question:** How does your work differ from the original ParoQuant algorithm?

**Answer:** The original method and public checkpoints provide the quantized weights and rotation parameters. I implement fused rotations, packed-format conversion, and matrix execution on Ascend, then validate complete-model performance and quality without relearning those parameters.

### 问题二 格式转换怎样保证权重含义不变

**中文回答：** 不能只重排四位编码，还必须一起处理有符号表示、偏移和缩放。独立参考会按原格式恢复权重，再检查新路径的结果，避免出现存储排列对了、数值含义却错了的情况。

**Question:** How do you preserve weight values during format conversion?

**Answer:** Conversion handles packed ordering, signed representation, zero-point adjustment, and scaling together. Independent references reconstruct weights from the original format and compare outputs, checking numerical meaning rather than storage layout alone.

### 问题三 为什么需要提前展开权重的强对照

**中文回答：** 每次完整展开权重的朴素实现很慢，只胜过它不足以说明价值。提前展开并缓存相同量化权重，再使用融合旋转，能检验紧凑执行本身的显存和速度取舍。

**Question:** Why do you include a strong dense baseline?

**Answer:** Repeated full dequantization makes the naive implementation very slow. A baseline that caches the same dequantized weights and uses fused rotations isolates the memory and latency tradeoff of packed execution against a practical alternative.

### 问题四 你能否宣称量化后更快且质量不变

**中文回答：** 不能。紧凑路径比强稠密对照省显存，但解码较慢，原始浮点模型也更快。质量方面，两个模型的数学题准确率与原始模型存在差异，应报告具体协议和数字。

**Question:** Can you claim faster inference with unchanged quality?

**Answer:** No. Packed execution uses less memory than the strong dense reference but has lower decode throughput, and the original BF16 models are faster here. Quality results also differ, so claims must include the measured values and evaluation protocol.

### 问题五 你怎样区分量化误差与执行误差

**中文回答：** 紧凑路径与展开路径使用同一套 PARO 权重，这个比较主要检查执行差异；再与原始浮点模型比较，观察已有量化对模型表现的影响。逐层参考、完整文本预测和数学题结果共同构成证据。

**Question:** How do you separate quantization effects from execution effects?

**Answer:** Packed and dense PARO paths use identical quantized weights, isolating execution differences. Comparing both with the original BF16 model examines the effects of quantization. Layer references, full-corpus perplexity, and GSM8K provide complementary evidence.
